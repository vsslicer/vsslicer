The judgement pass: every catalogue key gets one of the 14 groups and a home entity per the epic's table, hidden keys are flagged, and the override scope of each setting is recorded.

**Code:** `vsslicer/modules/profile-api/src/domain/catalogue/data/groups.json` and `vsslicer/modules/profile-api/tools/catalogue/` (module: `profile-api`, layer: n/a (generated data))

## Acceptance criteria

- [x] No key lacks a group or home entity; retraction keys live in `machine` with a material override
- [x] Group sums match the epic table within the documented `hidden` keys; a report lists the hidden keys with reasons
- [x] Each key has an `override_scope`; P1 groups (`multi_material`, `special`, `plate`) are present as schema and pass-through

## Tasks

- [x] Apply the group table
- [x] Review each hidden key against the VSS-3 dump
- [x] Record override scopes
- [x] Generate the group-count report

- **Judgement pass** in new `tools/catalogue/groups.ts`, run from `generate.ts` `outputs()` (still the only writer):
  - Orca and Bambu keys take the group of their own `Tab.cpp` page (`tabPlaces` scans the build functions, inlines `build_kinematics_page` and Orca's `PublishSettings.cpp` retraction/Z-hop lists once each, skips config reads and toggles, expands `"machine_max_jerk_" + axis`). `TAB_GROUPS` maps the pages onto the 14 groups, following the matrix's own mapping. An unmapped page throws. The home is the tab's entity (print: process, filament: material, printer: printer_model, plate tab: plate) where the group allows it; `nozzle_*` keys go to nozzle. A key on no page is `hidden` and keeps its nearest-category group.
  - SuperSlicer `superslicer.` keys take their `.ui` page's group (`UI_GROUPS`); off-page keys are hidden. Cura `cura.` keys take their category's group, mapped as the matrix maps them (resolution: layers, travel: extrusion, raft under adhesion, meshfix/blackmagic/experimental: special, ppr/command line: gcode). Two moves: start/end G-code goes to gcode, and `retraction_*`/`retract_*` (not combing) go to machine. `prusa.` keys keep their PRF-16 groups plus 4 fixes (`PRUSA_GROUPS`), because the 2.9 checkout has no Tab.cpp.
  - Retraction: Orca's printer extruder page (Retraction, Z-Hop, switching) is `machine`/`printer_model` with `overridable_in: [material]` wherever `filament_<key>` exists. Every remaining printer-homed `extrusion` key moves to machine (`retractionInMachine`; `prusa.travel_*` lift keys get the material override). Test: no printer-homed key is left in extrusion.
  - Prusa 3.0 sheet/feeder features: `prusa.hw_sheet_*` have home `surface` and `prusa.hw_feeder_*` home `feeder`. `GROUPS` machine homes gain surface and feeder (`src/domain/catalogue/entry.ts`), which replaces PRF-16's shortcut.
  - `override_scope` on every entry (`[]` = global). PrintRegionConfig keys get object, part, height_range. PrintObjectConfig keys get object (layer_height also height_range), read from each slicer's `PrintConfig.hpp`. Plate-tab keys add plate, plate-home keys get plate, and Cura `settable_per_mesh` keys get object and part. Prusa 3.0-only keys are global (marked shortcut). Scopes: 1150 global, 324 region, 262 Cura per-mesh, 184 object, 10 plate.
