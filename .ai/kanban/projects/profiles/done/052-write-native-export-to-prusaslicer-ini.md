Writes Prusa INI sections, flattened or with one `inherits` as PrusaSlicer stores user presets; an unmodified entity exports its stored native form byte for byte.

**Code:** `vsslicer/modules/profiles-prusa/src/adapters/export/prusa/` (module: `profiles-prusa`, layer: `adapters`)

## Acceptance criteria

- [x] Import then export of every user preset fixture is byte-equivalent (key order and number formatting kept through the native form); vendor presets per the "From PRF-43" idempotence criterion below
- [x] Only edited keys are re-formatted, by Prusa's rules (spike decision)
- [x] An unknown unified key produces a diagnostic and is left out of the file

From PRF-43 (`vsslicer/modules/profiles-prusa/docs/spikes/flatten-export.md`; these refine the first criterion above):

- [x] Vendor presets are checked for idempotence, not against the vendor section text (which cannot be rebuilt from the flattened form): `export(import(x))` bytes are stable and `import(export(import(x))).values` deep-equals `import(x).values`; user files PrusaSlicer wrote round-trip byte for byte
- [x] The native form keeps the source header line (`# generated by ...`, which carries a timestamp) and line ending, or the comparison covers bodies only; `PrusaNative` has neither field today
- [x] Edited keys are formatted by a port of `g()`/`canon()` from `.reference/notes/PRF-43-probe/probe.mjs`, using the option type table from PrusaSlicer's `PrintConfig.cpp` (`%g` precision 6, `,` joins, `%` on percent types, `nil`, `0`/`1`, the `coString` and `coStrings` escapers)
- [x] The native writer adds no type defaults, and leaves out non-type keys (`*_settings_id`, `renamed_from`, `octoprint_*`) when writing from unified data, keeping them only on a verbatim round trip

- [x] Bounds (rule 25, added by sp11-prf-52): at most `MAX_EXPORT_ENTITIES` (100 000) entities and `MAX_EXPORT_BYTES` (256 MiB UTF-8) of output per call, `MAX_KEYS_PER_SECTION` stored keys and settings per entity, no line over `MAX_LINE_LENGTH`; hostile input: a name with `/`, `\\`, NUL/control characters, `.`/`..` (path traversal) writes no file; a stored key with `=`/line break/`#`/`;`/`[` or a value with a line break (INI injection of a new section) is left out; two entities for one path, a malformed native form, non-object settings or entities never throw

How it works: an entity with a Prusa native form starts from its stored values verbatim. The stored lines are re-read
by `importPrusaIni` as a user file to get the settings the importer derives from them; settings that deep-equal those
keep their stored text (`0.20` stays `0.20`), changed or added ones go through `unifiedToNative('prusa')` and `canon()`,
removed ones drop their native lines. Keys keep the stored order, byte-sorted when the stored order was sorted
(as PrusaSlicer writes them); new keys join in sorted position then. An entity without a native form is written from
its settings alone, byte-sorted: no defaults, no `*_settings_id`/`renamed_from`/`octoprint_*`. `inherits`: one parent
(warning past one), or none (flattened). Output `print|filament|printer/<name>.ini`, LF, no header. Vendor and
`[printer_model]` sections are not presets (info diagnostic); a split nozzle (no settings of its own) is written from its
stored form. A changed `when` is reported, the stored condition kept.

Criteria evidence:
- User preset fixtures: `ini/user/print/My 0.15mm @MK4S.ini` gives back its body byte for byte; `default_fff.ini`
  (written by PrusaSlicer) round-trips byte for byte (body) as a print, filament and printer preset with 0 diagnostics;
  `ini/user-preset.ini` is hand-written with BOM, CRLF and padded values, which the importer trims, so it is checked for
