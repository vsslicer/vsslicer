- **Fixtures:** `test/tuples/fixtures/{orca,bambu}/`, the inherits/include closure of those presets copied unmodified from OrcaSlicer@09aa0114 and BambuStudio@79df7ae, with the vendor indexes cut to those files (218 files, 1.1 MB). `fixtures/PROVENANCE.md` records the source and licence (AGPL-3.0). No printer, no network (D5).
- **Oracle (as PRF-21 chose):** `test/tuples/golden/{orca,bambu}.json`, generated by `node test/tuples/generate-golden.ts`. It runs the installed OrcaSlicer-2.5.0-dev CLI with `--export-settings` on the fixture trees, from a mkdtemp cwd with a scratch `--datadir`. CI never runs it. Each tuple stores the normalised export value of every key we resolve; the Bambu tree export is the Orca cross-check. The generator fails on any key whose value differs in a way no named rule explains. Rules (`RULES` in oracle.ts, each citing OrcaSlicer@09aa0114:src/libslic3r): vector split/resize (Config.cpp:1004-1030, Preset.cpp:301), empty vector to default, string unquote, coPercent %, coPoint, thumbnails format, the handle_legacy rewrites (zig-zag, ensure_vertical_shell_thickness, negative ironing_angle/tree_support_wall_count, percent reset :9793-9803, extruder_clearance_max_radius rename :9962-9963). Each rule only applies to the keys handle_legacy names. Bookkeeping keys (`from`, `*_settings_id`, `compatible_printers`, `renamed_from`, `wall_infill_order`) are not compared. A key the export lacks is listed per tuple in `absent`. Those are Bambu-origin keys this CLI build does not know.
- **Bambu hand-checks:** 48 values over the 6 Bambu tuples, each citing the fixture `file:line` of the layer that sets it last (docs/research/profiles.md:94-102). Bambu-only keys are among them (machine_switch_extruder_time, prime_tower_lift_speed, filament_scarf_seam_type), as are include templates (machine_start_gcode prefix), inherited `filament_id` and own `setting_id`. Each was traced by hand through the chain.
- **Counts:** per tuple 194-409 keys are compared (H2C: 344, 328 exact and 16 through a rule). Over the whole golden set, 146 Orca-tree and 98 Bambu-tree key comparisons go through a rule.
- **Seeded merge-order bug, in-suite:** an independent hand merge of the raw fixture files with profile-api `merge` matches the oracle in Orca order for all 20. In "own, includes, parent" order it fails all 20, and in "includes under the parent" order it fails every BBL tuple.
