Writes Prusa INI sections, flattened or with one `inherits` as PrusaSlicer stores user presets; an unmodified entity exports its stored native form byte for byte.

**Code:** `vsslicer/modules/profiles-prusa/src/adapters/export/prusa/` (module: `profiles-prusa`, layer: `adapters`)

## Acceptance criteria

- [ ] Import then export of every user preset fixture is byte-equivalent (key order and number formatting kept through the native form); vendor presets per the "From PRF-43" idempotence criterion below
- [ ] Only edited keys are re-formatted, by Prusa's rules (spike decision)
- [ ] An unknown unified key produces a diagnostic and is left out of the file

From PRF-43 (`vsslicer/modules/profiles-prusa/docs/spikes/flatten-export.md`; these refine the first criterion above):

- [ ] Vendor presets are checked for idempotence, not against the vendor section text (which cannot be rebuilt from the flattened form): `export(import(x))` bytes are stable and `import(export(import(x))).values` deep-equals `import(x).values`; user files PrusaSlicer wrote round-trip byte for byte
- [ ] The native form keeps the source header line (`# generated by ...`, which carries a timestamp) and line ending, or the comparison covers bodies only; `PrusaNative` has neither field today
- [ ] Edited keys are formatted by a port of `g()`/`canon()` from `.reference/notes/PRF-43-probe/probe.mjs`, using the option type table from PrusaSlicer's `PrintConfig.cpp` (`%g` precision 6, `,` joins, `%` on percent types, `nil`, `0`/`1`, the `coString` and `coStrings` escapers)
- [ ] The native writer adds no type defaults, and leaves out non-type keys (`*_settings_id`, `renamed_from`, `octoprint_*`) when writing from unified data, keeping them only on a verbatim round trip
