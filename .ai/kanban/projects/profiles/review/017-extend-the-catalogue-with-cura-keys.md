Maps `Cura@5bea2f8:resources/definitions/fdmprinter.def.json` and `fdmextruder.def.json` (740 + 31 keys) onto canonical names, or `cura.` entries where none exists; `=expr` values are stored as `{expr}`.

**Code:** `vsslicer/modules/profile-api/tools/catalogue/` and `vsslicer/modules/profile-api/src/domain/catalogue/data/cura.json` (module: `profile-api`, layer: n/a (tooling and generated data))

## Acceptance criteria

- [x] Every Cura setting key is mapped or `native_only`; extruder-scoped keys are flagged per-extruder
- [x] Cura-only material properties from the XML key table (density, diameter, GUID) land in `material` entries, not settings
- [x] Formula defaults are kept verbatim and flagged `expr`
- [x] Bounds (rule 25): the Cura generator refuses a definition file over 16 MiB and settings nested deeper than 32 levels, and runs no upstream code; formulas are stored verbatim, never evaluated

## Tasks

- [x] Extract the definitions
- [x] Map to canonical names
- [x] Flag per-extruder and `expr` keys

## Progress

Done by sp7-prf-17.

- Generator `tools/catalogue/cura.ts` (imports only `render` from generate.ts) reads `Cura@5bea2f8` `fdmprinter.def.json`, `fdmextruder.def.json` (as JSON) and the XML key table in `plugins/XmlMaterialProfile/XmlMaterialProfile.py` (as text). Output `src/domain/catalogue/data/cura.json` (445 KB): `notice` (LGPL-3.0 + CC0), `entries` (637 `cura.` entries, `native_only: cura`, provenance `Cura@5bea2f8:<file>:<line>`), `names` (124 Cura names of Orca keys, hand table `CURA_NAMES` + `CURA_SPLITS`, with `lossy` notes and the obvious scale/sign_flip/split conversions; enum maps and percent-of conversions left to PRF-20), `per_extruder` (614 Cura keys: in fdmextruder or `settable_per_extruder` not false, its default being true, `cura/CuraApplication.py:415`), `material` (XML path -> Material field for GUID/brand/material/diameter/density, -> unified setting key for the 24 `<setting key>` names). 762 keys assigned once (740 + 31 definitions, 9 in both files). 300 defaults are `{expr}` (Cura `value` kept verbatim, wins over `default_value`); expression bounds are dropped, not evaluated.
- Loader `src/domain/catalogue/cura.ts`: `curaCatalogue`, types `CuraCatalogueFile`, `CuraMaterialKey`.
- Tests `test/catalogue-cura.test.ts` (14): schema validation of `entries`; each name valid as `native.cura` on its Orca entry; 762 keys once; per-extruder flags; `{expr}` verbatim; density/diameter/GUID as entity fields; notice/provenance; rule 25: file over 16 MiB refused before reading (sparse temp file) and a string over 16 MiB refused, depth 32 accepted / 33 refused, a hostile Python formula stored verbatim; on the pinned sources: deterministic and equal to committed data, 740 + 31, cited lines.
- Verified: `pnpm lint` clean, `pnpm test` 15 files / 293 tests pass, `pnpm build` ok. Regenerate: `node tools/catalogue/cura.ts`.
- Not done: `names` are not merged into orca.json (generate.ts/orca.json owned by PRF-16 this sprint); a merge step or loader can apply `names[k]` as `orcaCatalogue.entries[k].native.cura`. Groups/homes of `cura.` entries come from Cura's category plus key patterns (shortcut, commented).
