# Provenance

The module's own code (entity types, schema, condition and merge code, ports, the generator in `tools/catalogue/`) is original work written for VSSlicer, under the project licence (see `LICENSE`). The generated catalogue data in `src/domain/catalogue/data/` is ported from AGPL-3.0 slicers and stays under their terms, set out below. The port is allowed by decision D2.

## Catalogue data

`src/domain/catalogue/data/*.json` is generated by `tools/catalogue/generate.ts`, which reads the upstream C++ sources as text; nothing upstream is built or run. Do not edit the JSON; regenerate it. Each entry's `provenance` field names the upstream file and line it came from, and each file's `notice` field repeats the licence.

The short hashes in the data (`OrcaSlicer@09aa0114`, `BambuStudio@79df7ae`; `ORCA_COMMIT` and `BAMBU_COMMIT` in `tools/catalogue/generate.ts`) are these commits, as checked out in `.reference/repos/OrcaSlicer` and `.reference/repos/BambuStudio`. Copied: setting labels, tooltips, defaults, bounds and enum values, Copyright (C) the OrcaSlicer, Bambu Studio and PrusaSlicer authors.

Licence evidence:

- OrcaSlicer@09aa0114:README.md:260: "- **OrcaSlicer** is licensed under the GNU Affero General Public License, version 3." The README grants no "or any later version" option; the licence text is `LICENSE.txt` (AGPL-3.0).

So the generated catalogue data is AGPL-3.0-only. The package's SPDX `license` field must say so; owner question Q20 (card PRF-179) decides how. Not checked by a lawyer: whether a v3-only part makes the whole published package v3-only (AGPL-3.0 section 14).
