# Changelog

## 0.1.0

- Added: `readCuraProfile` reads a `.curaprofile` export as quality_changes entities with the parent quality_type in native and a setting_version diagnostic (PRF-112).
- Added: `fetchCuraResources(dest, options)` downloads Cura's definitions, extruders, variants and quality resources at a pinned commit (default Cura@5bea2f8) into a new folder with `source.json`: atomic placement, a bounded tar reader, an `idleTimeoutMs` option, a cache written only after the archive unpacks, and a retryable-error result (PRF-130).
- Fixed: Cura export writes boolean setting values as `True` and `False`, which Uranium can read (PRF-213).
- Fixed: Cura machine instance file names are decoded as quote_plus, so a machine id with a space finds its nozzle size (PRF-212).
- PRF-129: 22 Cura tuples (definition, extruder, variant, quality, user) checked against a hand merge of Cura@5bea2f8 resources (`test/tuples/`); `src/index.ts` formatted.
- PRF-127: `readCuraMachineInstances` reads `machine_instances/*.global.cfg` into printer-instance entities (model, nozzle, OctoPrint host, connection checked with `validateConnection`) with the API key returned apart.
- PRF-54: write user quality_changes and definition_changes as `.inst.cfg` (`setting_version` 27 for new files, `{expr}` back as `=formula`, metadata in the source order, keys Cura cannot read refused with a diagnostic): `writeCuraUserChanges`, `curaExporter`.
- Fixed: a Cura container or fdm_materials setting named `__proto__` keeps its metadata in `native` (PRF-209).
- PRF-31: read Cura `quality/` (`readCuraQualities`, 6 011 files) as `process` entities whose `when` is the definition/variant/material clauses; `quality_type` and the rest of `[metadata]` go to `native`. User `quality_changes` and `definition_changes` (`readCuraUserChanges`) import as a process and a `printer_instance` diff. Ids follow Uranium's `inst.cfg` suffix rule (including its lost last character on `h0.6inst.cfg`). `layer_height` falls back to the global quality, then the definition, then a 0.1 mm stand-in flagged in `native`. `readCuraResourceFolder` takes an optional folder list. Same per-call caps as PRF-30.
- PRF-32: read fdm_materials `*.xml.fdm_material` (v1.3) to `material` entities (`readFdmMaterials`, `readFdmMaterialFolder`) through profile-api's XML key table; GUID in `external_ids.cura_guid`; unmapped settings kept in `native`; `<machine>` overrides not read yet. The XML parser (saxes, as in `3mf`) refuses any DOCTYPE and caps depth, element count, text length, file count and bytes. `readCapped` is now exported from the folder reader. New dependency: saxes 6.0.0.
- PRF-30: read Cura `definitions/`, `extruders/` and `variants/` (`readCuraResources`, `readCuraResourceFolder`, `parseInstCfg`) with Uranium's inheritance (deep-merged `overrides`, `value` over `default_value`, shallow metadata); formulas stay `{ expr }`, never evaluated; `curaStackValue` and `CURA_STACK_SLOTS` give Cura's stack order. Caps per call on files, bytes, JSON depth, `inherits` depth and resolved entries; symbolic links are not followed and case or Unicode aliases of an id are read once.
- PRF-194: `.curaprofile` archives accept profile ids with a colon or a trailing dot or space (Cura derives ids from the typed name); the NTFS name rules are dropped because entries stay in memory. Empty, NUL, backslash, absolute and `.`/`..` names are still refused.
- PRF-131: read and write .curaprofile archives (flat STORED entries named by profile id, as Cura writes them) with entry-count, name-length, entry-size and total-size limits enforced while inflating.
- PRF-125: Cura quality metadata and `exclude_materials` convert to unified conditions (`convertQualityMetadata`, `curaMachineFlags`, `curaQualityDefinition`, `convertExcludeMaterials`); quality clauses follow the machine's `has_variants`, `has_materials` and `has_machine_quality`; `exclude_materials` is Cura's substring match; depends on `@vsslicer/profile-api` ^0.1.1.
- Module skeleton (`domain/`, `application/`), no public API yet.
